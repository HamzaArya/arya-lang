# Arya 1.3.0-alpha.4 — canonical syntax

This source candidate standardizes declaration, function, branch, loop, and output spellings. It remains unpublished and experimental. The last verified npm baseline recorded here is 1.2.0-alpha.4; no registry tag or published archive is changed by this source update.

## Breaking change

Use `const`, `fn`, `return`, `if`/`else if`/`else`, `for`, and `print`. The parser no longer accepts `keep`, `task`, `give`, `when`, `otherwise`, or `each` as their alternatives, and the generated runtime no longer declares `say`. Mutable bindings retain `let`.

Removed words become ordinary identifiers, so user declarations and properties with those names remain available. An undeclared `say(...)` reports `ARYA_UNKNOWN_NAME`. Library APIs such as `ui.when(...)` are unchanged.

The [syntax migration guide](../syntax-migration.md) lists replacements, contexts, and upgrade checks. Both block and concise function bodies, async functions, pipelines, parameter defaults/rest, spreads, guards, indexed `for` loops, finally cleanup, views, module graphs, and the Node.js/npm/Python contracts retain their behavior.

## Tooling and examples

- Generated web/API/CLI/UI/desktop starters, runnable fixtures, and active documentation use canonical syntax.
- Compiler keywords, builtin metadata, completions, hover help, semantic roles, TextMate/Vim/Emacs/nano grammars, generated adapters, snippets, the editor tour, and UI source highlighting agree on the reduced language surface.
- The canonical conformance fixture replaces the earlier branded fixture. Tests cover rejected aliases, reclaimed identifiers, callbacks, async/export contexts, source positions, passive analysis, and the retained canonical behavior.

Use a matching compiler/editor package. An AryaCode companion does not upgrade that IDE's separately pinned embedded compiler. Rebuild generated modules/maps after migration. Earlier released archives and versioned historical records retain their original syntax and hashes.
