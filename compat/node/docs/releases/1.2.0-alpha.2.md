# Arya 1.2.0-alpha.2 — HTML-first web projects

This local preview introduces a conventional web-project structure: an Arya server, a required HTML entry, and separate CSS/JavaScript assets. It retains the branded core syntax and optional inline views from alpha.1. This version does not establish npm/GitHub publication, a stable release, or additional platform qualification.

## New behavior

- `arya init [directory] --web` creates `main.arya`, `index.html`, `public/styles.css`, `public/app.js`, a project README, and `.gitignore`. Omitting the directory initializes the current folder. Existing destination files are not overwritten.
- `web.serve(3000)` starts an HTML-first application without requiring a route object. Its default entry is `index.html` beside the original Arya module importing `web`.
- GET/HEAD `/` serves the HTML entry. Public assets are served with appropriate content types from `public/`, with explicit API routes taking precedence.
- The optional `root`, `html`, and `assets` settings select other locations. `{html: false}` explicitly selects an API-only or inline-view application.
- The studio example now uses an ordinary HTML page, an accessible calculation form, separate browser assets, Arya API tasks, and an optional Python endpoint.
- New examples, editor snippets, and completion suggestions use `if`/`else if`/`else` for concise conditions. `when`/`otherwise` remain supported compatibility aliases.
- Functions keep `fn` and `return` as their preferred spellings, including generated web projects, documentation, editor snippets, and completions. `task` and `give` remain supported compatibility aliases.

See the [web guide](../arya-web.md) for the complete project layout and runtime contract.

## Compatibility decision and migration

The default HTML requirement intentionally changes alpha.1 startup behavior. An application with no HTML entry now fails before the server listens, with an actionable entry-file error. Either create the default `index.html` or explicitly opt out when the application is API-only or uses inline markup:

```arya
use std "web" as web

# alpha.1 allowed this without an HTML file:
# web.serve(3000, {"/": "Hello"})

# alpha.2: explicitly select inline content:
web.serve(3000, {"/": "Hello"}, {html: false})
```

For the default structure, use:

```sh
arya init my-app --web
arya run my-app/main.arya
```

Paths are tied to the original importing Arya source, so running generated output from a different working directory does not change its website root. The compiler does not bundle or relocate HTML/static files. Keep those files at their configured locations and rebuild after moving a project.

The alpha.1 reserved-word migration remains in effect. This preview does not change core syntax, native semantics, JavaScript/npm imports, or Python's synchronous JSON bridge. The default web server still uses Node HTTP; it does not require Express.

## Limits and validation

HTML, CSS, and browser JavaScript files are served as written. Passive Arya Check does not validate browser-file syntax or connect to external services. Static serving is limited to the configured entry/public directory and rejects traversal paths, dotfiles, and symlink escapes; it does not provide directory listings.

The native profile still excludes the web server, browser views, npm/Python imports, and MySQL adapter. Existing stable/community and cross-platform gates remain open. Actual check output and package evidence establish local qualification; the version label alone does not.
