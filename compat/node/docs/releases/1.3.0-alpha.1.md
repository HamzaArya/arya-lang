# Arya 1.3.0-alpha.1 — focused Node.js applications

This source candidate makes Node.js the single Arya execution runtime. It concentrates development on JavaScript/npm and Python integration, servers, databases, UI/animations, desktop apps, and dependable editor tooling.

**Publication status:** prepared source candidate; no npm publication is claimed. The verified public baseline remains 1.2.0-alpha.4. A separate publication transaction is required before registry-based creators can install 1.3.0-alpha.1.

## Breaking changes

- Removed the C11 native backend/runtime, self-hosted native compiler/bootstrap, native workflow/benchmarks, and native-only fixtures.
- Removed the `arya-language/native` package export and native builder/emitter APIs.
- Removed the native project template. The five active templates are web, API, CLI, UI, and Electron desktop.
- Removed native target/C compiler settings from the portable extension and target switching from LSP.
- Retired CLI native flags and target requests. They fail with migration help rather than silently running another backend. Legacy explicit `--target js` and Node-only API target values remain compatible.

The documented JavaScript language semantics and application libraries remain available. `arya build` emits Node.js modules and maps. Python and Electron remain optional dependencies for their respective features; a C compiler is no longer part of source or package acceptance requirements.

Unknown `use std` names now produce the shared `ARYA_UNKNOWN_LIBRARY` diagnostic during source analysis, project checking, compilation, and editor diagnostics. Obsolete API target requests use `ARYA_UNSUPPORTED_TARGET`.

The build clears its generated output so an old native bundle or type declaration cannot enter a new package. Shared branded-syntax and safe-access fixtures moved to `fixtures/arya/conformance/` and remain exercised on Node.js.

## Migration

Read [runtime and migration](../node-runtime.md) for commands, library replacements, API changes, candidate archive installation, and deployment boundaries. Native-only imports and runtime/memory assumptions require source changes; renaming a file or changing one flag does not promise equivalent behavior.

Earlier source and native implementations remain in Git history at `1d3d553`. Published artifacts, checksums, immutable tags, and their versioned qualification evidence are preserved. Historical native guides are explicitly marked as retired.
