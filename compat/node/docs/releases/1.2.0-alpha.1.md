# Arya 1.2.0-alpha.1 — branded syntax and single-file web applications

This experimental preview adds Arya spellings for common logic and a JavaScript-target web layer. It retains existing language spellings and the native command-line profile. This version identifies the source candidate and local artifacts; it does not declare npm/GitHub publication, a stable release, or new platform qualification.

## New behavior

- `keep`, `task`, `async task`, `when`/`otherwise`, `each`, and `give` express constant bindings, functions, decisions, iteration, and returns. `say` prints values. Existing `const`, `fn`, `if`/`else`, `for`, `return`, and `print` remain supported.
- `view { ... }` generates HTML from element blocks, attributes, class shorthand such as `body bg-dark`, and escaped text expressions. Literal `style` and `script` elements embed CSS and browser JavaScript.
- Triple-quoted strings preserve multiline text without backslash escaping.
- JavaScript-profile `use std` libraries supply `web.serve`/`web.response`, asynchronous text-file helpers, `math`, and an optional `mysql2` adapter that returns row data directly.
- Portable VS Code grammar and snippets recognize the new spellings and multiline web content.

The [web guide](../arya-web.md) describes grammar, APIs, execution boundaries, dependency requirements, and examples. Run `npm run arya -- run fixtures/web/studio.arya` after building this checkout.

## Compatibility decision and migration

The six new keywords are reserved. Older bindings named `keep`, `task`, `when`, `otherwise`, `each`, or `give` must be renamed. For example, change `let task = {title: "Learn"}` to `let item = {title: "Learn"}` and update its references. `say` is now a built-in and cannot be redeclared in module scope; rename an older top-level binding with that name. Property names and quoted object keys continue to follow the core grammar.

The existing syntax keeps its semantics:

```arya
# Existing form:
const threshold = 60
fn passed(score) {
  if score >= threshold { return true } else { return false }
}
print(passed(80))

# Arya 1.2 form:
keep threshold2 = 60
task passed2(score) {
  when score >= threshold2 { give true } otherwise { give false }
}
say(passed2(80))
```

The new core spellings are supported by both the JavaScript compiler and native compiler. Web views and Node-specific standard libraries require the JavaScript target. Native programs retain their own library and runtime contract.

## Limits and qualification

The web layer uses Node HTTP rather than requiring Express. Existing Express/npm imports still work through `use js`. The MySQL helper requires a separately installed `mysql2` package and a reachable MySQL server. The Python bridge retains its synchronous process-per-call JSON contract.

Embedded JavaScript runs in the browser; surrounding Arya and Python calls run on the server. This preview does not provide automatic reactive UI state, a browser-side Arya runtime, a static-site packaging pipeline, arbitrary Python object transport, or native web/database support. Check does not execute dependencies or validate embedded CSS/JavaScript.

Compiler, runtime, HTTP, view escaping, syntax migration, and editor regression tests supply local implementation evidence. Actual passing check output and artifact checksums establish the tested candidate; the version label alone establishes no qualification. Existing stable/community and cross-platform gates remain open. The package retains Apache-2.0, NOTICE, and third-party notices.
