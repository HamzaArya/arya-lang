# Arya 1.2.0-alpha.4

This experimental alpha brings the UI and motion library, offline editor setup, service tools, managed MySQL connections, asynchronous Python integration, and syntax/debugging improvements into one npm release. The intended distribution tag is `latest`, selected by the owner for the `npm install arya-language@latest` workflow. The alpha version remains an experimental compatibility contract.

## Install and create

Requires Node.js 22.15 or newer:

```sh
npm install arya-language@latest
npx --no-install arya editor install
```

Create a UI application with its own pinned compiler:

```sh
npm create arya-language@latest my-app -- --template ui
cd my-app
npm install
npm run dev
```

The creator offers `web`, `api`, `cli`, `native`, `ui`, and `desktop`. UI and desktop starters now support registry dependencies as well as portable `--compiler` archives. The compiler is published before the matching creator so generated projects can resolve its exact version.

## Changes

- `use std "ui"` supplies styled components, responsive layouts, browser state, form bindings, conditional views, JSON requests, dialogs, tabs, feedback, and animations. The built-in `ui.preview()` includes live components, a motion playground, copyable examples, and an implementation guide. See the [library reference](../../compat/node/docs/ui-library.md).
- UI and Electron desktop templates share an Arya application. The Electron renderer is isolated from Node; privileged operations go through server routes. Desktop builds require Electron and a graphical environment. `npm run build` compiles the application; desktop installers/signing remain a separate distribution task.
- The npm compiler archive includes an offline VSIX, file icons, Arya Dark/Light themes, richer grammar scopes, semantic highlighting, an editor tour, and portable adapters. `arya editor status`, `path`, and `install` configure detected VS Code-compatible editors, including AryaCode. npm installation downloads the assets; enabling the extension is an explicit command. See [editor setup](../../compat/node/docs/editor-setup.md).
- MySQL APIs add managed pools, prepared queries, transactions, result helpers, and environment configuration. Install `mysql2` in the application when using the database library. See [MySQL](../../compat/node/docs/mysql.md).
- Service APIs add runtime validation, structured logs, request IDs, parameter routes, readiness, cooperative deadlines, and controlled shutdown, including idle HTTP socket cleanup. See [services](../../compat/node/docs/services.md).
- Python integration adds asynchronous bound imports, keyword arguments, batches, queue limits, cancellation, interpreter inspection, and explicit virtual environments. Python and imported Python packages remain separate requirements. See [Python integration](../../compat/node/docs/python-async.md).
- `??`, optional access/calls with `?.`, and multiline method chains simplify problem solving. Diagnostics add source excerpts, hints, spelling Quick Fixes, JSON check reports, and a `debug` library. Native/bootstrap checks cover the supported safe-access syntax. See [syntax and debugging](../../compat/node/docs/syntax-and-debugging.md).

## Compatibility and qualification

The JavaScript target runs on Node. Native C11 remains a command-line profile without the Node web/UI/database/Python runtime. Native builds require a C11 toolchain. Existing source aliases and HTML/CSS/JavaScript web applications remain supported; older published archives do not gain these APIs.

MySQL connection verification and result validation are stricter than the earlier preview: `connect` verifies connectivity, `rows` expects row results, and write-result packets belong to `execute`. Optional access skips evaluated keys/arguments when its receiver is nullish; nullish defaults retain `false`, zero, and empty strings.

Release verification uses a recorded source snapshot, TypeScript/unit/integration checks, installed-package acceptance, editor archive/legal audits, and native bootstrap evidence. Browser, Electron, editor-host, and live-database qualification are recorded only when those optional checks actually run. Current local qualification is macOS arm64; this release does not declare stable or fresh Linux/Windows qualification.

The publication transaction and registry artifact verification are recorded separately after successful publication. GitHub releases and editor-marketplace publication are separate operations.
