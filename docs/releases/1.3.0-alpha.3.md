# Arya 1.3.0-alpha.3 — UI sections and templates

This source candidate expands the Node.js UI library. It is not published to npm; the latest verified public baseline remains 1.2.0-alpha.4. Build this checkout or use a matching candidate archive for these additions.

## Added

- Ten components: container, buttonGroup, image, descriptionList, timeline, steps, pagination, segmented, search, and meter.
- Eight reusable sections: navbar, hero, features, pricing, testimonials, FAQ, CTA, and footer.
- Four customizable full-page templates: landing, dashboard, settings, and sign-in. `ui.templates()` lists their names; `ui.template(name, options)` renders a complete document.
- New sections/template galleries, full-page preview routes, copyable Arya examples, and an expanded implementation guide.
- Shared API reference/member hints, editor snippets, responsive styles, and theme support.

See the [section/template contracts and examples](../../compat/node/docs/ui-patterns.md) and [UI reference](../../compat/node/docs/ui-library.md).

## Integration and compatibility

Existing UI APIs and the alpha.2 syntax contract remain supported. New page renderers do not automatically register routes. Template content/state are fresh per render; common page options and template-specific data/actions can be supplied. Body components append to the template's content. Unknown template options report `ARYA_UI`.

Settings and sign-in defaults explicitly show preview feedback. Applications implement saving, authentication, sessions, and billing. Use `submitAction` with a validated server endpoint. Password state must start empty. Example prices, quotes, identities, and dashboard data are sample content.

Images use the existing escaped URL/CSP rules, with explicit alternative text. Segmented controls use native radios; steps are a progress display and pagination accepts application-owned links. Search provides an input/clear action; application filtering remains explicit. The new semantic HTML elements pass through the existing bounded renderer and attribute rules.

The candidate remains experimental. An interface template does not establish stable language support, accessibility certification, or a hosted backend.
