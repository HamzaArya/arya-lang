# Arya 0.2.0-alpha.3 — modules and interoperability

9 November 2026. This development preview adds M4 Arya module graphs and M5 bridge hardening. It also provides installation, compatibility, security, community-review, and evidence-selection materials. It is not a stable 1.0 release.

## Modules

```arya
use arya "./lib/math.arya" as math
print(math.add(2, 3))
```

```arya
# lib/math.arya
export fn add(left, right) { return left + right }
```

One Check/Build/Run resolves the contained graph. Imports are relative with an explicit `.arya` suffix; the canonical entry directory is the CLI project root. Symlink aliases share one module identity. Missing sources, cycles, invalid exports, and missing direct namespace members receive source-positioned diagnostics. Named exports retain live ESM behavior. Every generated module has its own original-source map, including failures in a dependency.

Generated paths mirror source paths under `.arya/build`. AryaCode uses the same builder inside its fingerprinted `.arya/run` directory and adds workspace containment. A complete graph is staged before output publication. Failed graph builds never launch stale output; unrelated maps, symlinks, special files, and unowned output files are rejected rather than overwritten. Caller-selected output directories are exclusively generated storage. Cancellation before publication preserves the previous graph.

The asynchronous `arya-language/project` API exports `buildProject`, `checkProject`, `writeProject`, and `ProjectError`. Single-module compile/editor analysis stays synchronous and filesystem-free; it records imports/exports without fetching dependencies. See the [API contract](../compiler-api.md) and [module specification](../arya-specification.md#11-arya-modules-and-build-graphs).

## Interoperability

Python errors now expose stable `ARYA_PYTHON_*` codes for missing interpreters/modules/files, invalid members/arguments/input/returns, exceptions, timeouts, output limits, exit failures, and malformed protocol responses. Messages retain earlier stable prefixes and add actionable hints. The worker explicitly uses UTF-8, validates the response envelope, and bounds captured stderr forwarding on process start/timeout/buffer failures; ordinary and Python-exception logging retain the 8 MiB subprocess bound. Its process-per-call, 30-second timeout, 8 MiB buffers, JSON data restrictions, and fresh state are preserved. Cycles/custom serialization errors consistently use TypeError with `ARYA_PYTHON_INPUT`; malformed but syntactically valid response envelopes now reject instead of returning undefined.

JavaScript calls retain native namespace/default/CommonJS, callback, receiver, constructor, promise, numeric, and stack behavior. Nullish default selection remains the M2 rule. Missing JavaScript properties are runtime concerns; direct Arya namespace exports can be checked because their graph is available. See the [interop guide and complete examples](../interop.md).

## Migration and limits

- Existing single-file CLI commands and compile overloads remain supported. For multiple Arya files, prefer `use arya` over manually compiling/importing `.mjs` files.
- Run a root-level entry when dependencies occupy sibling directories. Imports cannot escape the selected root; a dependency imported through a symlink is resolved from its canonical file location.
- Build now replaces its owned generated graph as a unit. Keep personal data out of `.arya/build`/`.arya/run` and other explicit output directories. Legacy generated module/map pairs are recognized.
- Bare npm resolution follows the generated module tree and the entry project's parent `node_modules` chain. Dependencies installed only under an original nested source folder are not automatically relocated; install at the entry root or use a source-relative JS helper.
- Projects are bounded to 1024 canonical Arya modules and 16 MiB total source. Per-file/compiler/range/Python limits still apply.
- Python exception text may include action hints. Use `error.code` for categorization instead of matching the full message. Native stdout writes that bypass normal Python logging can corrupt the protocol and are rejected.
- Static module checks do not add a type system, dynamic-property validation, parser recovery, an interactive debugger, or a persistent Python worker. The documented runtime host-shadowing limitation remains.
