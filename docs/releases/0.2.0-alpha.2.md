# Arya 0.2.0-alpha.2 — lexical checks (local preview)

9 November 2026. M3 adds lexical name resolution and const-write validation to every compilation, including `arya check`, Build/Run, portable editor diagnostics, LSP, and AryaCode's embedded provider. Analysis remains synchronous and never imports JavaScript, probes missing packages, starts Python, or executes user code.

Unknown bare names report `ARYA_UNKNOWN_NAME` with exact UTF-16 token ranges and, for a unique close name, a spelling suggestion. Direct and compound writes to const, import aliases, and Arya built-ins report `ARYA_CONST_ASSIGNMENT`. Mutation of an object through a const binding is allowed. Declaration kinds and read/write references are recorded in a completed lexical scope graph; forward functions, recursion, captures of later bindings, nested shadowing, loop/catch boundaries, and M2 runtime TDZ behavior are preserved. The resolver uses the documented host-global allowlist independently of the analysis host.

A complete parse reports independent semantic diagnostics together. Syntax failure still reports one diagnostic; parser recovery is outside this release. Semantic errors retain top-level completion and Outline data. Same-file go-to-definition follows parameters, closures, loop/catch bindings, imports, and declarations; properties and host/builtin names have no local target. Missing dependency availability, property existence, runtime types, and declaration-initialization timing remain runtime concerns. The existing generated-runtime host-shadowing limitation is documented in the specification.

## Migration from alpha.1

Programs that previously caught an unknown name or const reassignment at runtime now fail before execution, including errors in unused functions or unreachable branches. Correct the spelling/scope or declare/import the name. Use `let` for a binding that must change; import aliases and Arya built-ins cannot be reassigned. Unknown optional host names require an explicit `globalThis` property access or `use js` import.

```arya
# Before: only failed when executed
let greeting = "hello"
print(greetng)

# After: correct the name
print(greeting)
```

```arya
# Before: runtime const assignment error
const count = 1
count += 1

# After: choose a mutable binding
let total = 1
total += 1
```

The first examples intentionally fail Check. `const item = {count: 1}; item.count += 1` remains valid. A closure may refer to a later declaration; execute it after initialization. Function declarations remain callable earlier in their scope. Property names are not lexical names, so checking `box.name` does not validate that `name` exists.

The CLI success message changes from `Syntax OK` to `Check OK`. Automation should use exit status. Error lines retain source file/line/column formatting and may now contain several independent diagnostics. Both legacy `compile(source, filename)` and the options form remain supported and enforce the same checks.

The compiler API adds `analyzeSource` and resolution metadata. `AryaError.message` and `.token` remain the first error; `.diagnostics` contains the complete diagnostic list. The language-service API adds `.diagnostics`, `.bindings`, `.references`, and `definitionAt`; `.error` remains the optional first-diagnostic alias. See the [API contract](../compiler-api.md) and [normative specification](../arya-specification.md).

Shipped acceptance examples: `fixtures/arya/check/unknown-name.arya`, `const-write.arya`, and `valid-scopes.arya`. Clean-package tests check both intentional failures and run the valid closure/mutation example. The resolver, CLI, LSP, embedded IDE provider, and standalone extension have corresponding regression coverage.

Validation on macOS arm64: all 43 language tests pass on Node 22.15.0 and 24.16.0; clean-installed package acceptance passes on both runtimes. AryaCode's 61-test suite passes. Both embedded-provider and independent standalone-extension desktop acceptance pass, including multiple diagnostics, UTF-16 spans, passive analysis, same-file definitions, completion/Outline with errors, and live-edit recovery. Existing source-map, JavaScript/Python, and Run/Stop acceptance remains passing.

This is a local prerelease. Licensing, public publication, first-class Arya module graphs (M4), and Linux/Windows qualification remain separate roadmap gates.
