# 1.3.0-alpha.10 — reliability and developer workflow candidate

**Unpublished candidate.** Compiler and creator versions are `1.3.0-alpha.10`;
the portable extension version is `1.3.5`. Published alpha.9 archives, registry tags
and publication records remain the original release. This candidate adds the
unreleased workspace, library and compiler work listed in the [changelog](../../CHANGELOG.md).

## Changes

- Keep testing assertions compatible with Node 26 by omitting absent optional
  arguments without dropping required undefined values.

- Distinguish declared types from current flow types; check branch joins, loop and
  exception writes, compound assignments and conservative captured-write effects.
- Prevent unsafe widening of mutable record/array aliases and check indexed writes
  against element contracts. A fresh literal can initialize a wider shape.
- Read default/CommonJS exports, local aliases, single ambient modules and bounded
  non-generic overloads. Exercise real pinned npm packages and TypeScript consumers.
- Discover closed workspace files, cache unchanged module analyses and support
  static cross-file references/rename with explicit discovery limits. Enable source
  breakpoints through a Node adapter and exercise real editor rename/buffer/debug
  workflows in isolated profiles.
- Separate parser/emitter phases, select requested standard runtimes, bound AST
  depth and retain repeatable benchmarks and seeded malformed-input cases.
- Format core source with a pinned formatter; separate type representation and
  write effects into focused modules and enforce formatting in `npm run check`.
- Generate feature availability in current guides from one record and prepare a
  [learner exercise](../../compat/node/fixtures/examples/learner-review/README.md) and
  [observation record](../../compat/node/docs/learner-review-session.md).

See [behavior and limits](../../compat/node/docs/editor-and-compiler-improvements.md), including the
security/testing source additions documented separately in their guides.

## Compatibility

These stronger checks can reject annotated programs accepted by alpha.9. After
reassigning a nullable variable, guard its new value before reading members. Use a
const snapshot for callbacks that need an already checked value. Avoid widening an
existing mutable record/array alias; initialize the intended wider shape directly
or make an explicit copy. Annotations still insert no runtime validation, and
unannotated modules retain dynamic behavior.

Generic/advanced declarations, arbitrary host effects, proxy/getter behavior and
full alias/exception analysis remain outside the bounded checker. Source limits
and workspace rename limits are documented explicitly. General TypeScript parity
and cross-runtime object transport are not promised.

## Qualification

Run `npm run check`, `npm run test:editors`, appropriate browser/Electron/database
checks, and `npm run test:clean`. The clean verifier records the exact source
inventory, lockfile, runtime, command results, installed-package acceptance and
archive hashes under `.build/evidence/`; `.build/clean-candidate-record.json`
identifies the retained source snapshot. Use those exact reviewed archives.

Local results do not qualify other operating systems. The 12-job CI matrix must
run on this candidate's eventual source revision. Real learner sessions, an agreed
maintenance policy and any untested optional integrations remain separate gates
for stable release. The owner will recruit participants using the prepared kit.
No package publication or stable-release declaration is performed by qualification.
