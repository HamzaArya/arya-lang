# Arya 0.2.0-alpha.1 — local preview

This local prerelease adds standard source maps and mapped CLI runtime stacks. The compiler API accepts `{filename, outputFilename}` and returns `{code, map, mapFilename, symbols, usesPython}`. The legacy filename call remains available.

`arya build` writes an adjacent `.mjs.map`. `arya run` enables Node source maps automatically. Standalone output needs `node --enable-source-maps generated.mjs`. AryaCode consumes the exact same archived package and enables the flag in its normal runner.

Tests cover original file/line/column, function caller frames, multiline expressions, `await`, Python/built-in failures, Unicode, spaces, distinct expressions on one line, map metadata, and containment.

M1 qualification now includes CLI Build followed by standalone Node execution, passive Check, syntax failures preserving previous code/map artifacts, and literal program arguments. The 16-test suite passes on macOS arm64 with Node 22.15.0 and 24.16.0; clean-installed package acceptance and five AryaCode integration tests also pass on Node 22.15.0 with Python 3.13.15. A Linux/Windows/macOS CI matrix is configured; Linux/Windows qualification remains pending. See [source-map acceptance](../source-maps.md).

The package remains private with inherited `UNLICENSED` metadata. Nothing has been published. The portable extension uses numeric version `0.2.0`, preview status, and `aryaLanguageVersion: 0.2.0-alpha.1` because VSIX versions do not use npm prerelease suffixes.

Next: finish the specification/conformance decisions, lexical checks, relative Arya module builds, interop hardening, and clean release qualification. See the [roadmap](../arya-roadmap.md).
