# Arya 1.3.0-alpha.2 — readable application flow

This Node.js-only source candidate adds useful expression/control-flow syntax and an input-first collection library. It remains an experimental candidate; npm latest still identifies the published 1.2.0-alpha.4 baseline. No new npm publication is claimed.

## Added

- Input-first `|>` pipelines and explicit `|> await` stages, with input evaluated once, deterministic evaluation order, and preserved method receivers.
- Expression-bodied named/anonymous functions, default values, and rest parameters.
- Iterable spreads in lists, calls, and constructor argument lists.
- `guard condition else { ... }` with a checked terminating fallback.
- Indexed iteration through `each value at index in iterable`.
- `try/finally` and `try/catch/finally`, including awaited cleanup in async contexts.
- `use std "list"` with map, flatMap, filter, find, reduce, groupBy, sortBy, take, unique, and sum. Selectors can use field names; sorting preserves input and equal-key order.
- Updated snippets, semantic/TextMate roles, portable keyword sets, source diagnostics, and starters that demonstrate concise functions.

See the [complete syntax contract and examples](../../compat/node/docs/flow-syntax.md).

## Compatibility

Existing block functions and source spellings remain supported. The new reserved binding word `guard` requires renaming older identifiers; properties/object keys with that name remain valid. `finally` was already reserved. `at` is contextual, and the new operators occupied previously unsupported syntax.

Pipelines never implicitly await. Optional-chain stage targets require selecting an ordinary callable first. Rest parameters must be last; spreads apply to list/call contexts rather than object literals. Parameter defaults have a separate initializer environment and cannot see body declarations. The public parsed AST now includes default expressions, pipeline/spread nodes, optional loop indexes, and optional catch/finalizer blocks; custom AST visitors must handle them.

The Node.js-only changes from [alpha.1](1.3.0-alpha.1.md) remain in force. Historical native and published package archives remain unchanged. New syntax/list APIs require this candidate's compiler and cannot be used with the older npm archive.
