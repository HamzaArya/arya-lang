# Arya 1.2.0-alpha.3 — interactive project creation and root rendering

This experimental preview adds an interactive creator, npm-managed project templates, and a web starter that mounts all application content inside div#root. The compiler and creator were published to npm on 9 November 2026. This does not declare a GitHub release or new stable/platform qualification.

## Behavior and compatibility

- `arya create` and unqualified `arya init` ask for a project directory and type: web, API, CLI, or native CLI. `--template` and `--yes` support automation. EOF or Ctrl+C cancels; no dependencies are installed automatically.
- The new `create-arya-language` companion package implements the npm initializer convention for `npm create arya-language`. The compiler also exposes `arya-language` and `create-arya` creator executables for npx and direct use.
- All templates include a package manifest with a pinned compiler dependency and dev/start/check/build npm scripts. Registry commands require both exact package versions to be published.
- Web index.html is a single shell with div#root. Browser JavaScript renders the page and all request results within that element. Separate CSS and browser module files remain under public/; main.arya supplies the server.
- `--compiler path.tgz` includes a version-matched compiler archive as a relative vendor dependency. The resulting source folder can be moved before npm install, without publishing or depending on the compiler repository.
- The existing `arya init directory --web` shortcut is retained. It now generates package.json and the root-mounted client; older projects are not rewritten. `arya init` without a template formerly failed usage validation and now asks questions.

The preferred source spellings remain fn, return, const/let, and if/else, while the earlier aliases remain accepted. No parser/runtime semantics are changed in this preview. Native scripts still require a C11 toolchain, and web apps still run on Node.

## Migration and limits

For older generated projects, keep the existing HTML/browser code or adopt the new root shell and render into it. New starters no longer place visible application markup directly in index.html. Update any tests selecting page elements before the browser module has mounted the application.

Use npm create or npx for project creation. Plain npm install remains noninteractive. The project creation workflow does not add Vite's bundler, HMR, React/JSX, automatic dependency installation, or a new deployment/build pipeline. npm run build retains Arya's existing compiler output contract.

See the [creator guide](../../compat/node/docs/project-creator.md) and [web guide](../../compat/node/docs/arya-web.md) for exact commands, local-preview installation, file paths, and runtime boundaries.

## Local validation — 9 November 2026

- `npm run check` passed all 141 tests and TypeScript checking, including wizard input/selection/cancellation, all templates, root rendering with a live API call, protected publication/rollback, and previous language/native checks.
- `npm run package:editors` built the compiler tarball, creator tarball, VSIX, and editor kit with SHA-256 checksums.
- `npm run test:package` installed both packed packages, exercised the actual offline `npm create arya-language` command and both npx executables, then copied a generated project with its vendored compiler to a different directory. Installation with a new empty npm cache, npm run check, and npm run build passed there.
- The native three-generation bootstrap passed for this version, including generated-C convergence and the existing conformance checks.

These are local results on macOS arm64. No visual browser acceptance, live MySQL-server qualification, or additional OS qualification is claimed.
